About

My work sits across AWS infrastructure, CI/CD automation, container platforms, and monitoring. Most days that means Terraform state and drift, Docker image size and layer caching, Kubernetes probe tuning, and reading pipeline logs to work out why a release stalled at 2am.

I care about the parts of a system that only reveal themselves when something breaks: health checks that actually detect a bad release, rollback to a known-good version, backups you have restored from rather than merely created, and a rough idea of your RTO and RPO before you need them. Security checks run on every build too — Trivy for images, OWASP Dependency-Check for dependencies, quality gates in SonarQube — rather than as a separate step someone remembers to do.

Career changer into DevOps. The engineering fundamentals came from an electrical background; the daily work now is automation, infrastructure as code, and reliability.

Configuration Management with Ansible

Ansible, YAML, Jinja2, Ansible Vault, Ubuntu, Apache Tomcat, Nginx
What it does
  • Wrote Ansible roles for Tomcat and Nginx — defaults, tasks, handlers, and Jinja2 templates — replacing shell scripts run over SSH that had to be repeated against every server by hand.
  • Achieved idempotency so a repeat run reports changed=0, using get_url with force=false, check tasks with changed_when=false, and handlers notified only by tasks that can genuinely change.
  • Applied variable precedence across role defaults, group variables, and host variables, so a single playbook targets multiple environments by overriding only the values that differ.
  • Used check mode with --diff for dry runs before applying, and separated a read-only verify-idempotency playbook from the deploy path.
  • Encrypted credentials with Ansible Vault, rendered the application environment file at 0640 permissions, and validated Nginx with nginx -t before reloading so a bad config never takes the site down.
Structure
  • 3 roles (common, tomcat, nginx) and 14 YAML files, with site.yml as the entry point and three playbooks for deploy, config validation, and idempotency checks.
